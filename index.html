AdGuard Home – setup guide

AdGuard Home,set up properly.

It filters ads and trackers for every device on your network, and it ships with defaults tuned for a safe first boot rather than a working home. This guide walks through each screen in the order the interface presents them and says what to set and why. If you read only one thing, read the six rules.

01

Encrypt the connection

Pick an upstream address that starts with quic://, https:// or tls://. A plain number like 8.8.8.8 means your internet provider can still read every site you visit.

02

Let only AdGuard Home block things

Your upstream servers must not do any blocking of their own. Otherwise a site fails to open while the log insists it was allowed, and you have no way to find out why.

03

One big list is enough

The lists in the General group are 80–95% the same domains. A second one costs you full memory and blocks almost nothing new.

04

Security lists are the exception

Malware and phishing lists are built from different sources, so running two or three together really does catch more than one alone.

05

Turn on one list at a time

After each one, wait for its rule count to appear, then check free memory. Switching on several at once can crash the service with no useful error.

06

Nothing is filtered until your devices use it

AdGuard Home only sees traffic that is sent to it. Enter its address as the DNS server in your router, so every device on the network is covered at once.

Upstreams

Provider list ↗ Upstream docs ↗

Upstreams are the servers AdGuard Home forwards to once it has checked a query against your lists. Two rules govern the choice: the connection must be encrypted, and the resolver must not filter. Every resolver listed on this page is non-filtering, because AdGuard Home is already doing that job – a filtering upstream would block domains your log reports as allowed.

Which protocol

The prefix on an address decides how the query travels. When a resolver offers several, take the highest one on this list.

Protocol Encrypted Verdict Notes
DNS-over-QUIC quic:// Yes Preferred No TCP handshake, so the first query is fast and packet loss hurts less. The best choice when the resolver offers it.
DoH over HTTP/3 h3:// Yes Preferred The same speed benefits as QUIC, and it looks like ordinary web traffic. Refuses to fall back to HTTP/2.
DNS-over-HTTPS https:// Yes Fine Port 443, indistinguishable from web browsing, so it survives restrictive networks. Slightly more overhead than QUIC.
DNS-over-TLS tls:// Yes Fine Port 853, simple and widely supported. That dedicated port also makes it trivial to spot and block.
DNS Stamp sdns:// Yes Fine A packed string describing a DNSCrypt or DoH server including its key. Convenient, but you cannot read it at a glance.
Plain DNS over TCP tcp:// No Not upstream Avoids truncation on large answers but adds no privacy at all. Your provider still reads every query.
Plain DNS over UDP (none) No Not upstream A bare IP address. Fine in the bootstrap field, wrong as an upstream: everything travels in the clear.

DNS server settings

Two of these are a recurring source of failures that look random: a rate limit of 20 quietly drops normal traffic bursts, and AAAA lookups run into timeouts on IPv4-only networks. Fix those two and most mystery slowdowns disappear.

Check your version first. Several 2026 releases hardened how AdGuard Home validates answers from DoH and DNSCrypt upstreams and how it handles QUIC connections, so an old build undoes part of what this page sets up.

Blocklists and the memory they cost

AdGuard Home holds every rule in RAM, and lists overlap by 80–95% while memory is charged per rule. So the question is never which list is best, it is how many rules your hardware can carry and which of them are not duplicates.

Set your hardware below, tick lists in the tables, and the counter at the top of the screen tells you whether the set fits.
